# Nabu audit, 2026-11-16 (Phase 0)

Scope: the working tree on `main` (6 commits, plus 45 modified and 24 untracked
paths not yet committed) and the artifacts under
`$MODELS_ROOT/projects/nabu`. Checked by reading the code and running
`make test-go test-py lint-go lint-py`: all Go packages pass, 50 Python tests
pass, lint is clean. No translation, retrieval or TTS quality number is
reported here, because none has been measured yet.

## 1. What exists

| Area | State |
| --- | --- |
| Architecture | Go for everything that runs (`g2p`, `script`, `data`, `translate`, `tts`, `api`), Python only for training (`tts/train`, `translate/train`), React demo (`web`). Six Go modules in one `go.work`, a uv workspace, CI with six jobs. |
| Sources | 7 verified, pinned (URL + SHA-256) sources in `data/source/source.go`: TLA Earlier/Late/Demotic, AES, AED, Coptic lexicon (all CC BY-SA 4.0), Unikemet (Unicode-3.0). ORACC and CDLI are registered but unverified, so `fetch` refuses them. No Hittite source. |
| Corpus | `build-corpus` merges to 81,700 sentences and 44,700 lexicon entries, with AES converted to TLA conventions and deduplicated. By source and stage: AES unknown-stage 32,969, AES earlier 23,695, TLA demotic 12,461, TLA earlier 9,216, TLA late 3,359. 19,352 sentences have hieroglyphs. Translations are German. |
| Retrieval | BM25 over the German of TLA Earlier only, plus a flat-file vector index (Qwen3-Embedding 0.6B via Ollama, 512 dims, float16, brute-force cosine) over the whole corpus, fused with RRF. Stage filter keeps `earlier` and unknown. |
| Translation | LLM (default `qwen3:4b-instruct` via any OpenAI-compatible server) prompted with 8 examples and 10 glossary entries; one correction round for out-of-alphabet graphemes; per-word attestation and a "confidence" share; examples and glossary returned with IDs and attributions. CLI and `POST /v1/translate`. |
| Script | Attested spelling from a TLA lexicon, sign-by-sign fallback labeled as unattested. |
| G2P | A solid rule engine (YAML, contexts, longest match, golden tests, WASM build) with one rule file, `egy-allen`. |
| TTS | VITS adapted from the MIT reference, IPA-code-point input, shared symbol table with hash checks, ONNX export with parity check, Go runtime on ONNX Runtime, MLflow logging. |
| Evaluation | Go `nabu-translate eval`: chrF, exact match, attested share, foreign-word share on a held-out split (90/5/5 by text group, own text hidden from retrieval). |
| Fine-tuning | `export-sft` (prompts built by the inference code), mlx-lm LoRA wrapper with smoke and full configs, `backfill-en` to machine-translate the German into English. |
| Storage | `MODELS_ROOT` drives every path in Make, Go, Python, compose and `start.sh`; an unmounted `MODELS_ROOT` is an error in each. |

## 2. What is weak

1. **Pronunciation is a placeholder.** `g2p/rules/egy-allen.yaml` says so
   itself: conventional consonant values, none taken from Allen, and no vowels
   at all. `ꜥnḫ` becomes `ʕnχ`. A voice cannot say that, so the speech stage
   has nothing real to speak. The file is also named after a reconstruction it
   does not implement. There is no second convention to choose from.
2. **No trained voice, and the plan does not fit the hardware.** Only the
   synthetic smoke checkpoint exists. `full.yaml` assumes CUDA, batch 32 and
   800k steps from scratch, with an empty donor list; the machine is a 16 GB
   Apple Silicon Mac mini. No Common Voice data has been downloaded.
3. **Nothing has been measured.** `checkpoints/llm/` is empty and there is no
   eval report. The fine-tuning tooling was built before a baseline exists,
   which is the reverse of the order the decision gates require.
4. **The test set is not English → Egyptian.** References are corpus
   sentences whose input is the editors' German. English inputs come only from
   `backfill-en` (a 4B model translating German), which has not been run, and
   would put translation noise on the input side of both training and test.
   No sentence has been reviewed by an Egyptologist.
5. **Stage contamination.** 32,969 AES sentences have no settled stage and
   are treated as usable Middle Egyptian for retrieval and training. AES
   includes temple-library and Late Period tomb corpora; how many of the
   unknown-stage sentences come from them is not yet counted. That is 3.5 times
   the TLA Earlier set, so it can dominate both examples and fine-tuning data.
6. **Retrieval is unevaluated and lopsided.** No gold query set, no recall@k
   or MRR. The embedding model was not compared with anything. BM25 covers
   only TLA Earlier and needs an extra LLM call to guess German keywords.
   Dictionary entries are found by dense search alone: there is no exact
   lookup on English glosses or on transliterated lemmas, which is the
   cheapest and most precise signal available (15,875 AED entries have English).
7. **"Confidence" overstates.** It is the share of output word forms that
   occur anywhere in the corpus. It says nothing about meaning or grammar,
   output words are not linked to the lemma or gloss that justified them, and
   during evaluation the form list still contains the test sentences.
8. **Thin provenance schema.** A record carries source, stage, date and ID,
   but no license, no reliability tier, no page or line reference, and the
   original (pre-normalization) AES transliteration is discarded.
9. **Metrics are split and partly missing.** chrF lives in Go; `eval/` is a
   Python stub whose test asserts `NotImplementedError`. No chrF++, BLEU,
   lexical exact match or grammar-phenomenon tests. No TTS check beyond
   listening to five words.
10. **Docs drift.** README lists PostgreSQL + pgvector as the vector store
    (the code uses a flat file), says `eval/` is Go, and omits Akkadian from
    the language table. `translate/README.md` lists as "not done" three
    things that exist in the tree.

## 3. What is missing against the brief

- A source registry as data (YAML/JSON) with reliability tier, access method,
  robots/ToS status, retrieval date and an ingest/reference/reject decision.
  Today it is Go code and a hand-synced markdown table. No generated NOTICE.
- Grammar, phonology and transliteration-convention content in the knowledge
  base. It holds sentences and dictionary entries only.
- A vector-store comparison and an embedding-model comparison.
- A reranker experiment, a data-quality report per source, a gold query set.
- Configurable pronunciation conventions (reconstructed, Coptic-based,
  Egyptological reading) with a documented default.
- Baseline (a) LLM without retrieval and (b) LLM with retrieval, as numbers.
- TTS evaluation protocol, and evidence for or against VITS in this regime.
- Research-cycle command, error-analysis tooling, contributor correction path.
- One config file. Settings are spread over env vars, Makefile defaults,
  `.env` and per-tool YAML.

## 4. Mismatches between the brief and the repository

- **Language.** The brief asks for Python 3.11+ throughout. The repository is
  deliberately Go at runtime ("no Python at request time") and already has
  ingestion, retrieval, translation and evaluation in tested Go.
- **Yale and Michigan data.** Nothing in the repository uses them. An earlier
  check (2026-11-16) found no openly licensed Egyptian dataset from either;
  every source in use is BBAW/TLA-derived or KELLIA.
- **Pretrained TTS.** The brief asks to evaluate fine-tuning from a
  multilingual checkpoint. `tts/train/README.md` forbids pretrained TTS
  weights, non-commercial licenses and espeak-ng, even for labels. Those rules
  exclude several well-known multilingual checkpoints; which remain is a
  Phase 1 question.
- **Fail loudly.** An unmounted `MODELS_ROOT` fails. An *unset* one silently
  falls back to directories inside the repository. The agent shell does not
  have it set.

## 5. Top risks

1. **Vocalization.** Without a sourced, explicit way to supply vowels, speech
   output is not defensible. This is the hardest scholarly problem in the
   project and currently has no design.
2. **TTS feasibility.** From-scratch multi-speaker VITS on this machine is
   unlikely to finish; the licensing rules narrow the pretrained options.
3. **Evaluation validity.** German-pivot references, machine-translated
   English and mixed-stage data can make a model look better or worse than it
   is. Any training decision made on them would be weak.
4. **Tiny, formulaic corpus.** About 9k to 33k clean Middle Egyptian
   sentences, heavy on offering formulae and funerary texts. Fine-tuning risks
   memorized formulae and confident invention outside them.
5. **Share-alike.** Every corpus is CC BY-SA 4.0. Two decisions in
   `DATA_LICENSES.md` are still open (served outputs, committed sign counts).
6. **Uncommitted work.** Most of the RAG, corpus, eval and fine-tuning code
   exists only in the working tree.

## 6. Proposed layout

Keep the Go runtime and the module boundaries. Add, do not rewrite.

```
sources/registry.yaml     single source of truth for sources (new)
sources/README.md         generated summary; NOTICE and DATA_LICENSES.md generated too
data/                     Go ingestion, reads the registry (pins and checksums stay)
kb/                       Go: record schema, normalization, hybrid index, quality reports (new;
                          retrieval code moves here from translate/)
translate/                Go: prompt, generation, uncertainty flags
g2p/rules/                one file per convention: egy-egyptological (default candidate), others sourced
eval/                     gold sets (retrieval queries, translation pairs, grammar probes) and
                          the harness; one implementation of each metric
research/                 research-cycle command, error analysis, corrections queue (later phases)
tts/, tts/train/          unchanged until the TTS investigation
nabu.yaml                 one config file; env vars override; MODELS_ROOT required
```

Language-specific pieces (stage filter, transliteration normalizer, alphabet,
prompt) sit behind a per-language definition so Sumerian, Akkadian and Hittite
add data and rules, not code paths. Nothing is built for them yet.

## 7. Proposed order

1. Source registry and research (Phase 1), including what can supply
   vocalization and which TTS checkpoints the license rules allow.
2. Gold sets and baselines with the current system, before changing it.
3. Cheap retrieval fixes (exact gloss and lemma lookup, stage handling), each
   measured against the gold set; then the vector-store and embedding
   comparisons.
4. Pronunciation conventions and the TTS investigation.
5. Training proposal only if a measured gap remains.
