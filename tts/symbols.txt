# Nabu TTS input symbol table. Shared by the Python trainer (tts/train) and
# the Go runtime (package tts), which embeds this file.
#
# Format
#   One entry per line. The token id of an entry is its index among
#   non-comment lines, starting at 0. A line is whitespace-separated fields:
#     <symbol> [<alias> ...] [# comment]
#   Aliases are tokenized to the same id as the symbol. A field is either a
#   single code point written literally, a code point written as U+XXXX, or
#   one of the special names <pad> and <space>. Lines starting with # are
#   comments; a field starting with # starts a trailing comment.
#
# Tokenization (implemented identically in Go and Python; see the shared test
# vectors in tts/testdata/):
#   1. Normalize the IPA string to Unicode NFD, so diacritics are separate
#      code points (e.g. U+00E3 becomes a + U+0303).
#   2. Trim whitespace and collapse each run of whitespace into one <space>.
#   3. Map every code point to its id. A code point that is not in this table
#      is an error. Nothing is ever dropped.
#   4. If the model uses add_blank, insert <pad> between all tokens and at
#      both ends (VITS convention).
#
# Rules for editing
#   * APPEND ONLY. Never reorder, delete or change existing lines: token ids
#     are baked into every trained model. Models record a hash of this table
#     and the runtime refuses to load a model trained on a different table.
#   * Adding entries changes the hash too, so existing models must be
#     retrained (or re-exported after resizing the embedding) to use it.
#   * This is the IPA character set, not a claim about any language's
#     phoneme inventory.
